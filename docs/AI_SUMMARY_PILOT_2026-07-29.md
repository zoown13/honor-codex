# 조례 AI 정제 10건 파일럿 결과

- 실행일: 2026-07-29
- 모델: Amazon Nova 2 Lite (Bedrock global inference profile)
- 실행 범위: 전체 후보 1,432건 중 지자체 분산 안정 표본 10건
- 자동 승인·게시: 하지 않음

| 지표 | 결과 |
| --- | ---: |
| 요청 | 10건 |
| 구조화 결과 생성 | 8건 |
| 실패 | 2건 |

비용은 애플리케이션에 설정된 입력·출력 토큰 단가로 계산한 값이며 AWS 청구서 확정액과 다를 수 있습니다.

## 원문 대조 품질

8건을 공식 원문 발췌와 비교한 결과, 그대로 승인 가능한 수준으로 판단한 결과는 1건이었습니다. 나머지는 게시하지 않고 검수 대기로 유지했습니다.

- 1건: 병역명문가 대상·증빙·이용 방법을 원문 범위 안에서 유용하게 정리
- 2건: 병역명문가가 포함됐지만 다른 감면 대상까지 함께 나열해 혜택 범위가 모호함
- 4건: 원문에 병역명문가 근거가 있으나 결과의 대상 또는 요약에서 병역명문가를 누락
- 1건: 병역명문가 원문 발췌가 없는 조례가 후보에 포함된 오탐

이 결과는 모델 자체보다 후보 데이터와 프롬프트가 “조례 전체 감면 대상”을 요약하도록 열려 있었던 점이 주요 원인이었습니다. 전체 1,432건 실행은 품질 기준을 충족할 때까지 진행하지 않습니다.

## 즉시 반영한 개선

1. 기본 작업 크기를 서버 제어 10건으로 제한했습니다.
2. 안정 해시와 지자체별 round-robin으로 표본을 선택하고, 승인 시 혜택 ID와 원천 content hash를 고정합니다.
3. 원문 발췌에 `병역명문가`가 없는 조례를 후보에서 제외했습니다. 이 필터로 현재 후보는 1,340건이 됐습니다.
4. 프롬프트가 다른 감면대상을 제외하고 병역명문가 및 가족에게 적용되는 내용만 추출하도록 변경했습니다.
5. 결과의 요약과 대상에 `병역명문가`가 없으면 캐시나 검수 변경으로 저장하지 않는 품질 게이트를 추가했습니다.
6. 프롬프트 버전을 작업 지문과 캐시 키에 포함해 개선 전 결과가 다음 실험에서 재사용되지 않게 했습니다.
7. DynamoDB 종료 상태 조건의 예약어 문제를 수정하고, 모든 항목을 처리한 작업을 상태 조회 시 멱등 복구하도록 했습니다.

## 다음 실험의 합격 기준

현재 8건을 승인·게시하지 않고 정리한 뒤 별도 10건 표본으로 다시 평가합니다. 다음 조건을 모두 만족하기 전에는 전체 실행을 검토하지 않습니다.

- 관련 원문 없는 후보 0건
- 요약·대상에서 병역명문가 누락 0건
- 원문에 없는 할인율·증빙·절차 생성 0건
- 10건 중 최소 9건이 경미한 문구 수정만으로 승인 가능
- 모든 결과가 원문 URL, content hash, 모델, 토큰 사용량을 보존

## 대외 제안에 활용할 근거

이 파일럿은 “AI로 전량 자동 게시”가 아니라 공개 원천 데이터를 저비용으로 구조화하고 사람이 최종 검수하는 보조 흐름이 현실적임을 보여줍니다. 병무청 협의 시에는 다음 지원을 구체적으로 요청해야 합니다.

- 병역명문가 예우시설·혜택의 정식 API와 변경 이력 또는 안정적인 데이터 파일
- 자동 수집·캐시·재배포에 관한 명시적 이용 조건
- 공식 담당부서의 정기 검수 또는 오류 제보 채널
- 오픈소스 코드 인수·공동 운영·공식 서비스 연계 중 가능한 운영 모델
